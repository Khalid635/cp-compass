# CP Compass PWA — Service-Worker Caching Design

## Assumptions

- The manifest already exists (`name "CP Compass"`, `display: standalone`); this design adds only the worker, `start_url`/`scope` of `/`, and registration.
- `/sw.js` is served from the site root (Vercel) with `Cache-Control: no-cache` (in `vercel.json`); otherwise the browser may miss a new worker for up to 24 hours. The worker never talks to the Render backend.

## Design principles

Default-deny: the worker caches **only** the public shell bytes listed below. Nothing else is ever stored — no API response, no header, no user-specific byte — so a shared device cannot leak one user to another and logout needs no cache purge. Every failure falls through to the network or an explicit offline message, never to a silently stale response.

## 1. Cache names and versioning

```js
const VERSION = 'v1'; // Bump only when a precached URL changes content.
const SHELL_CACHE = `cp-shell-${VERSION}`;   // precached shell
const ASSET_CACHE = `cp-assets-${VERSION}`;  // hashed bundles, fonts at runtime
```

Bumping is hygiene, not correctness: hashed asset names are self-invalidating (new build, new URLs, old entries never requested), and navigations are network-first (§4), so an online user always gets the fresh shell even if a release forgets the bump. `activate` deletes every `cp-*` cache not in the current set, bounding storage.

## 2. The worker (`frontend/public/sw.js`, complete)

```js
const VERSION = 'v1';
const SHELL_CACHE = `cp-shell-${VERSION}`;
const ASSET_CACHE = `cp-assets-${VERSION}`;
const PRECACHE_URLS = [
  '/', '/index.html', '/manifest.webmanifest', '/compass.svg',
  '/fonts/inter-var.woff2', // list every shipped woff2 here
];
const ALL_CACHES = [SHELL_CACHE, ASSET_CACHE];

self.addEventListener('install', (e) => {
  e.waitUntil(caches.open(SHELL_CACHE)
    .then((c) => c.addAll(PRECACHE_URLS))
    .then(() => self.skipWaiting()));
});

self.addEventListener('activate', (e) => {
  e.waitUntil(caches.keys()
    .then((keys) => Promise.all(keys
      .filter((k) => k.startsWith('cp-') && !ALL_CACHES.includes(k))
      .map((k) => caches.delete(k))))
    .then(() => self.clients.claim()));
});

self.addEventListener('fetch', (e) => {
  const { request } = e;
  const url = new URL(request.url);
  if (url.pathname.startsWith('/api/')) return; // network-only, untouched
  if (request.method !== 'GET' || url.origin !== self.location.origin) return;
  if (request.headers.has('Authorization')) return;
  if (request.mode === 'navigate') {
    e.respondWith(networkFirstNavigation(request)); return;
  }
  if (url.pathname.startsWith('/assets/') || url.pathname.startsWith('/fonts/')) {
    e.respondWith(cacheFirst(request, ASSET_CACHE)); return;
  }
  // Default deny: everything else goes to the network, uncached.
});

async function networkFirstNavigation(request) {
  try {
    const res = await fetch(request);
    if (res.ok) {
      const copy = res.clone();
      caches.open(SHELL_CACHE).then((c) => c.put('/index.html', copy));
    }
    return res;
  } catch {
    const cached = await caches.match('/index.html');
    if (cached) return cached;
    return new Response('CP Compass is offline. Reconnect to load the app.',
      { status: 503, headers: { 'Content-Type': 'text/plain' } });
  }
}

async function cacheFirst(request, cacheName) {
  const cached = await caches.match(request);
  if (cached) return cached;
  const res = await fetch(request);
  if (res.ok && res.type === 'basic') {
    const copy = res.clone();
    caches.open(cacheName).then((c) => c.put(request, copy));
  }
  return res;
}
```

## 3. Precache list

**Precached at install** (identical for every user): `/`, `/index.html`, `/manifest.webmanifest`, `/compass.svg`, every self-hosted woff2 under `/fonts/`. If any `addAll` entry fails, install fails and the old worker stays — a broken deploy never replaces a working shell.

**Deliberately NOT precached:** hashed JS/CSS under `/assets/` — names unknown until build time, changed every build; cached on first use instead (§4). No route HTML beyond `index.html` — the SPA fallback covers every route. Nothing under `/api/`, ever.

## 4. Fetch-handler routing

| Request | Strategy | Why |
|---|---|---|
| `/api/v1/*`, incl. `/sync/stream` SSE | **Network-only; handler returns before any cache logic** | Zero added latency, zero interception of the stream, zero chance of a cached private response. The worker never reads an `Authorization` header. |
| Navigations (`mode: navigate`) | **Network-first, cached-shell fallback** | Online users always get the freshest `index.html`; offline users still boot. Fresh responses update the cached shell. |
| `/assets/*` (hashed JS/CSS) | **Cache-first** | Filenames are content-hashed, so a cached entry is immutable; a miss fetches and caches only `200` same-origin (`basic`) responses. |
| `/fonts/*` (woff2) | **Cache-first** | Same immutability argument as assets. |
| Everything else (favicon, unknown paths) | **Network-only, never cached** | Default-deny: an unlisted URL cannot smuggle data into a cache. |
| Non-GET, cross-origin, or any request carrying `Authorization` | **Network-only, never cached** | No writes, no opaque responses, no credentialed responses are ever stored. |

## 5. Update flow

1. A deploy ships a byte-different `/sw.js` (usually with a bumped `VERSION`); the browser detects it on navigation or via the `visibilitychange` check in `main.tsx`.
2. The new worker installs, precaches the new shell into new versioned caches, then `skipWaiting()`.
3. On `activate` it deletes all old `cp-*` caches; `clients.claim()` takes control of future navigations.
4. **The user is never force-reloaded.** `main.tsx` shows a "New version available — Refresh" banner; reload happens only on tap. An auto-reload could kill a running sync. Until the user reloads, the open tab keeps running the old worker and shell — both still functional.

## 6. Offline behaviour

- **After one online visit:** any route loads offline — shell, bundles, fonts, logo all from cache. The app boots; API calls fail, so data views show their offline/empty state (nothing faked from cache).
- **Deep link offline** (e.g. `/app/dashboard`): the navigation fallback serves cached `index.html`; the router renders the dashboard shell, its data sections showing the offline state.
- **First-ever visit while offline:** nothing is cached, so the browser shows its standard offline error. Unavoidable, and stated here rather than papered over.

## 7. Registration (`frontend/src/main.tsx`)

```tsx
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js').then((reg) => {
      reg.addEventListener('updatefound', () => {
        const w = reg.installing;
        w?.addEventListener('statechange', () => {
          if (w.state === 'installed' && navigator.serviceWorker.controller)
            showUpdateBanner(() => window.location.reload());
        });
      });
      document.addEventListener('visibilitychange', () => {
        if (!document.hidden) void reg.update(); // checks /sw.js on Vercel only
      });
    });
  });
}
```

Production only, never in dev. No background or periodic sync — nothing ever wakes the sleeping Render backend; the only update check fetches static `/sw.js` from Vercel.

## 8. What is never cached, and recovery from a buggy worker

Never cached: any `/api/v1` response (including public `/demo/*` — today's public endpoint may not stay public), the SSE stream, non-GET requests, cross-origin or opaque responses, anything involving an `Authorization` header, and any non-`200` response. The caches hold only public shell bytes, so they are safe across users and across logout.

If the worker itself is buggy: (a) the next deploy ships a fixed `/sw.js`, whose byte change triggers an update on next navigation; (b) emergency kill-switch — deploy a no-op worker whose `activate` deletes all `cp-*` caches; (c) per-device escape — DevTools → Application → Service Workers → Unregister, or Clear site data. Because caches are versioned and the shell is network-first, a bad deploy self-heals for online users.

## 9. Verification

1. **No API response is cached:** browse logged in, open DevTools → Application → Cache Storage, confirm no entry under any `/api/` URL; repeat as a second user after logout — no first-user data appears.
2. **Shell loads offline:** DevTools → Network → Offline, reload, confirm the app boots; then open `/app/dashboard` while still offline and confirm the shell loads with offline data states.
3. **New deploy updates the shell:** bump `VERSION`, deploy, focus the tab, confirm the banner, tap Refresh, confirm the new hashed assets load and the old `cp-*` caches are gone.
4. **SSE untouched:** start a sync and confirm progress events stream live; `/api/v1/sync/stream` must show no "from ServiceWorker" source.
