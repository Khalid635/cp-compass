# CP Compass PWA — Service-Worker Caching Design

## Principles

1. **The cache holds only the public shell.** Nothing user-specific ever enters a cache, so shared devices can't leak and logout needs no purge.
2. **One versioned cache, nothing else.** A single cache name tied to the build; a new deploy creates a new cache and deletes the old one.
3. **The worker never touches API traffic.** `/api/*` and the SSE stream bypass the worker entirely — no interception, no cloning, no added latency.

## Cache name and versioning

```
CACHE = `cp-compass-shell-${BUILD_ID}`
```

`BUILD_ID` is the short git SHA plus UTC build timestamp (e.g. `cp-compass-shell-a1b2c3d-20261128T0430Z`), injected by a dependency-free post-build script, `scripts/inject-sw-manifest.mjs` (Node stdlib only), which reads `dist/`, replaces the `__BUILD_ID__` and `__PRECACHE_URLS__` placeholders in `public/sw.js`, and writes the final `dist/sw.js`. It also collects the hashed asset and font filenames — hashed names are never hand-written in source. On `activate`, the worker deletes every cache starting with `cp-compass-shell-` except the current one, so a unique `BUILD_ID` per deploy means no user is ever stuck on a stale shell.

## Precache list

**Precached at install** (same-origin, public): `/`, `/index.html`, `/manifest.webmanifest`, `/compass.svg`, every hashed `dist/assets/*.js` and `*.css`, every `dist/fonts/*.woff2` — the last two injected by the build script.

**Deliberately NOT precached:** everything under `/api/v1` (including the public read-only `/demo/*` — it is API data, and the `/api/` prefix rule must have no exceptions), any cross-origin URL, any non-`GET` request, and any response carrying `Set-Cookie` or `Cache-Control: no-store`/`private`.

## `frontend/public/sw.js` (complete)

```js
const BUILD_ID = '__BUILD_ID__'; // replaced at build time
const CACHE = `cp-compass-shell-${BUILD_ID}`;
const PRECACHE = ['/', '/index.html', '/manifest.webmanifest', '/compass.svg',
  ...__PRECACHE_URLS__]; // hashed assets + fonts, injected at build time
const SHELL_PREFIXES = ['/assets/', '/fonts/'];

self.addEventListener('install', (e) => {
  // A failed precache fails install and the old worker stays.
  e.waitUntil(caches.open(CACHE).then((c) => c.addAll(PRECACHE)));
});

self.addEventListener('activate', (e) => {
  e.waitUntil(
    caches.keys()
      .then((keys) => Promise.all(keys
        .filter((k) => k.startsWith('cp-compass-shell-') && k !== CACHE)
        .map((k) => caches.delete(k))))
      .then(() => self.clients.claim())
  );
});

self.addEventListener('message', (e) => {
  if (e.data?.type === 'SKIP_WAITING') self.skipWaiting();
});

self.addEventListener('fetch', (e) => {
  const { request } = e;
  const url = new URL(request.url);
  // Rule 0 — API, SSE, non-GET, cross-origin: bypass completely.
  // No respondWith: zero added latency, and the worker never sees
  // an Authorization header, request body, or response body.
  if (url.pathname.startsWith('/api/') || request.method !== 'GET'
      || url.origin !== self.location.origin) return;

  // Navigations: network-first, precached index.html as offline fallback only.
  // index.html is NEVER cache-first — that is how users get stuck on a stale shell.
  if (request.mode === 'navigate') {
    e.respondWith(fetch(request).catch(() => caches.match('/index.html')));
    return;
  }

  // Hashed assets, fonts, logo: cache-first. Names change every build,
  // so a new deploy misses the cache and fetches fresh; old entries die
  // with the old cache. Only same-origin GET 200 responses are stored.
  if (SHELL_PREFIXES.some((p) => url.pathname.startsWith(p))
      || url.pathname === '/compass.svg') {
    e.respondWith(caches.match(request).then((hit) => hit || fetch(request)
      .then((res) => {
        if (res.ok) {
          const copy = res.clone();
          caches.open(CACHE).then((c) => c.put(request, copy));
        }
        return res;
      })));
    return;
  }

  // Everything else same-origin: network-only, never stored.
  e.respondWith(fetch(request));
});
```

## Fetch-routing summary

| Request | Strategy | Why |
|---|---|---|
| `/api/*` incl. `/api/v1/sync/stream` (SSE) and `/demo/*` | Network-only, no interception | Private data must never be stored; a long-lived stream must never be cloned or delayed |
| Navigations (`/`, `/app/dashboard`, …) | Network-first → cached `index.html` | Fresh shell when online; offline fallback when not |
| `/assets/*`, `/fonts/*`, `/compass.svg` | Cache-first | Hashed/immutable: the name *is* the version |
| Everything else, same-origin | Network-only | Default is to store nothing |
| Cross-origin, non-`GET` | Bypassed | Never cached, never inspected |

## Update flow

The new worker installs in the background and **waits** — it does not call `skipWaiting()` in `install`, so it can never yank the shell out from under a running sync or an unsaved form. `main.tsx` (production-only registration) surfaces the update and lets the user choose when to take it:

```tsx
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  window.addEventListener('load', async () => {
    const reg = await navigator.serviceWorker.register('/sw.js', { scope: '/' });
    const offerUpdate = () => showUpdateToast(() =>
      reg.waiting?.postMessage({ type: 'SKIP_WAITING' }));
    if (reg.waiting) offerUpdate(); // an update installed while the tab was open
    reg.addEventListener('updatefound', () => {
      reg.installing?.addEventListener('statechange', (e) => {
        if ((e.target as ServiceWorker).state === 'installed'
            && navigator.serviceWorker.controller) offerUpdate();
      });
    });
    // Cheap: re-checks only the static /sw.js on Vercel, never the Render backend.
    document.addEventListener('visibilitychange', () => {
      if (!document.hidden) reg.update();
    });
    let refreshing = false;
    navigator.serviceWorker.addEventListener('controllerchange', () => {
      if (!refreshing) { refreshing = true; window.location.reload(); }
    });
  });
}
```

On the user's tap: `SKIP_WAITING` → new worker activates → old cache deleted → `clients.claim()` → single reload. If the user ignores the prompt, the waiting worker activates the next time all CP Compass tabs are closed and the app is reopened — nobody is stuck on an old shell, and nobody is force-reloaded mid-task.

## Offline behaviour

After one online visit, the shell loads with no network at all. Tapping a deep link such as `/app/dashboard` while offline serves the cached `index.html`; React Router renders the Dashboard route, and the app shows its own offline banner and empty state ("You're offline — your data will load when you're back"). API calls fail cleanly because they are network-only, so the app shows *no data*, never stale data and never another user's data. Login needs network; the `localStorage` token is invisible to the worker.

## What is never cached, and recovery from a buggy worker

Never cached: any `/api/v1` response, the SSE stream, any request with an `Authorization` header, any non-`GET` request, any cross-origin response, any non-200 response. Defence in depth: the backend also sends `Cache-Control: no-store` on all `/api/v1` responses. Vercel headers (`vercel.json`): `/sw.js` → `no-cache` (the browser must always re-check it); `/index.html` → `no-cache`; `/assets/*` → `immutable`. No background sync or periodic sync is used — nothing ever wakes the sleeping Render backend.

If the worker is buggy: a failed install leaves the previous worker in place and the site works online as before. Emergency kill-switch: deploy a one-line `/sw.js` that deletes all `cp-compass-shell-*` caches and calls `self.registration.unregister()`, then redeploy the fixed worker. Users can also unregister in DevTools → Application → Service Workers.

## Verification

**(a) No API response is cached.** Log in, use the app, then DevTools → Application → Cache Storage: only shell entries, zero `/api/` entries. In the console, `await caches.match('/api/v1/dashboard')` returns `undefined` and `await caches.keys()` lists exactly one cache. Repeat after logout and login as a different user.

**(b) Shell loads offline.** In DevTools, tick Offline, reload `/` and then navigate to `/app/dashboard`: the shell renders with the offline banner. Unticking Offline and reloading restores live data.

**(c) A new deploy updates the shell.** Deploy a build with a new `BUILD_ID`, load the app: the "New version available" toast appears; tap Refresh; Cache Storage now shows the new cache name and the old name is gone.

## Assumptions

The manifest already exists (name "CP Compass", `display: standalone`); ensure it also sets `start_url: "/"`, `scope: "/"`, and 192/512 px icons including a maskable one. Fonts are self-hosted woff2 with no Google Fonts dependency. The backend adds `Cache-Control: no-store` to `/api/v1` responses. Browsers are modern Chrome/Edge/Firefox/Safari.
