# CP Compass PWA — service-worker caching design

Hand-written worker, no new dependency, no Workbox. Files: `frontend/public/sw.js`, `frontend/public/manifest.webmanifest` (unchanged), a few lines in `frontend/src/main.tsx`, headers in `vercel.json`. Production only, never dev. No background or periodic sync.

## Worked example — one concrete build

Deploy 47, 28 Nov 2026: `index.html` references `/assets/index-B8f2c1a9.js` and `/assets/index-D4e5f6a7.css`; fonts `/fonts/inter-latin-400.woff2`, `/fonts/inter-latin-700.woff2`; logo `/compass.svg`. Khalid visits online: the worker precaches the stable shell; the hashed JS/CSS enter the assets cache on first fetch. Offline, he reopens `/app/dashboard`: the shell renders, with an offline banner and "dashboard data needs a connection" — no stale data. Deploy 48 ships new hashed assets; his next online reload fetches the new `index.html` network-first.

## 1. Cache names and versioning

```js
// frontend/public/sw.js
const VERSION = 'v3'; // bump v3 -> v4 on EVERY frontend deploy (release checklist, one line)
const SHELL_CACHE = `cp-shell-${VERSION}`; // index.html, fonts, logo, manifest
const ASSETS_CACHE = 'cp-assets'; // unversioned: keys are hashed URLs, so content versions itself
```

The shell cache is versioned so a deploy can discard the old shell; the assets cache is unversioned because a hashed filename *is* its version — `index-B8f2c1a9.js` can never silently become different bytes. `activate` deletes every cache except these two.

## 2. Precache list

Precached at install with `cache: 'reload'`. If any entry fails, install fails and the old worker stays in control — never a half-installed shell.

**Precached:** `/`, `/index.html`, `/compass.svg`, `/manifest.webmanifest`, `/fonts/inter-latin-400.woff2`, `/fonts/inter-latin-700.woff2`.

**Not precached:** hashed `/assets/*` — names are unknowable in static `public/sw.js`; cached at runtime on first fetch (§3). Anything under `/api/v1/*`, including public `/demo/*` — decided by path, never by judging content. `/icons/*`, favicon — on demand, stale-while-revalidate; not shell-critical.

## 3. Fetch-handler routing

Privacy gate first. If any condition holds, return **without `event.respondWith`** — the request goes straight to the network, with zero worker latency, zero cloning, zero chance of caching:

```js
self.addEventListener('fetch', (event) => {
  const url = new URL(event.request.url);
  if (event.request.method !== 'GET') return;
  if (url.pathname.startsWith('/api/')) return; // ALL /api/v1, incl. /demo/*, /api/v1/sync/stream (SSE)
  if (event.request.headers.has('Authorization')) return; // defence in depth, whatever the URL
  if (url.origin !== self.location.origin) return; // no third-party response is ever cached
});
```

So the worker never sees, stores, or replays an `Authorization` header, and POST/PUT/DELETE can never be cached. The SSE stream is untouched — no `respondWith`, no clone, no buffering — so a 50-second Render cold start costs no more than without a worker.

| Request | Strategy | Why |
|---|---|---|
| Navigation, any SPA route | Network-first, cache fallback | Online: newest `index.html` (new hashed assets). Offline: cached `/index.html`. Only `200` cached, under key `/index.html`. |
| `/assets/*` | Cache-first, network fallback | Hashed filenames are immutable; a hit can never be stale. On a miss, cache only `200`, same-origin, `type === 'basic'` responses. |
| `/fonts/*`, `/compass.svg` | Cache-first | Stable filenames, updated by the `VERSION` bump. |
| `/icons/*`, manifest, favicon | Stale-while-revalidate | Not shell-critical; serve instantly, refresh in background. |
| Everything else, incl. `/api/*` | Network-only, no `respondWith` | Gate above. |

## 4. Update flow

1. Every navigation re-fetches `/sw.js` (forced by `Cache-Control: no-cache`, §6). A byte change — the `VERSION` bump — installs a new worker.
2. Install precaches the new shell, then `self.skipWaiting()`. Activate deletes all caches except the two current ones, then `self.clients.claim()`.
3. The open tab keeps running its loaded JS; its next navigation fetches new `index.html` network-first anyway.
4. The app shows a "New version available — Reload" banner on `registration`'s `updatefound` event; the button is `window.location.reload()`. No forced reload, no silent swap mid-task.
5. Old-tab race, patched: the assets cache is unversioned, so an old tab still running Deploy 47's `index-B8f2c1a9.js` keeps working after Deploy 48 activates. Only the shell cache is replaced.

```tsx
// frontend/src/main.tsx — production only
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js', { scope: '/' }).then((reg) => {
      reg.addEventListener('updatefound', () => showUpdateBanner());
      document.addEventListener('visibilitychange', () => { if (!document.hidden) reg.update(); });
    });
  });
}
```

## 5. Offline behaviour

Loads offline after one online visit: the shell (`index.html` + hashed JS/CSS + fonts + logo), the login page, any SPA route renderable without data. Never loads offline: dashboard, submissions, settings, sync status, demo data — all `/api/v1`.

Deep link `/app/dashboard` while offline: the worker serves cached `/index.html` (URL preserved, no redirect to `/`), React Router mounts the dashboard route, and the app shows an offline banner plus "You're offline — dashboard data needs a connection." The login form renders offline but sign-in fails with a plain network error. Logout needs no cache purge: the shell cache holds no user data, and the token lives only in `localStorage`, which the worker never touches.

## 6. Not cached, and recovery from a buggy worker

Not cached: every `/api/v1` response (authenticated or public `/demo/*`); any request with an `Authorization` header; any non-GET request; any cross-origin response; any non-`200` response (a cached error page would poison the shell); the SSE stream.

Recovery: (1) Kill-switch — deploy a replacement `/sw.js` whose `install` calls `skipWaiting()`, whose `activate` deletes **all** caches and calls `registration.unregister()`; remove it on the next deploy so a fresh worker registers. (2) If the worker cannot be reached, clear site data for the origin (DevTools → Application → Clear site data); the app then loads with no worker. (3) `vercel.json` headers, without which the design fails: `/sw.js` → `Cache-Control: no-cache`; `/index.html` → `public, max-age=0, must-revalidate`; `/assets/*` → `public, max-age=31536000, immutable`.

## 7. Verification

**(a) No `/api` response is cached.** Log in, browse dashboard, submissions, settings, start a sync. DevTools → Application → Cache Storage: only `cp-shell-vN` and `cp-assets` exist, with zero keys containing `/api`. Network tab: no `/api/v1` request shows "(from ServiceWorker)". Log out, log in as a second account: the dashboard shows the second account's data.

**(b) Shell loads offline.** One online visit, then DevTools → Network → Offline, reload `/`, then reload `/app/dashboard`: shell renders, offline banner shows, no stale data. Repeat in the installed PWA and in Firefox/Safari.

**(c) New deploy updates the shell.** Bump `VERSION`, deploy, reload once online: Service Workers shows the new worker active, Cache Storage shows the new `cp-shell-vN` and the old one gone, and the loaded script tag's hash differs from the previous deploy's. Confirm the banner path via `reg.update()` in the console.

## Attack-tested — five hostile cases, each patched above

1. **Shared device:** B logs in after A and gets A's cached dashboard. *Patch:* `/api/*` network-only by path, plus the `Authorization` gate; the caches cannot hold A's data.
2. **Tab open for weeks:** the user never reloads, so the new worker never activates. *Patch:* `visibilitychange` → `reg.update()`; network-first navigation serves the new `index.html` even under the old worker.
3. **Sync stream breaks:** the worker clones/buffers SSE or adds latency to a sleeping backend. *Patch:* `/api/*` returns before `respondWith` — the worker never touches the stream.
4. **New deploy breaks the old tab:** activate deletes the old hashed JS the running tab needs. *Patch:* the assets cache is unversioned; only the shell cache is replaced.
5. **Buggy worker caches a 500 error page as the shell.** *Patch:* only `200`, same-origin, `basic`, GET responses are cached; install fails atomically; kill-switch in §6.

## Assumptions

Fonts have stable filenames under `/fonts/`; the logo is `/compass.svg`; the manifest already has `start_url: "/"`, `scope: "/"`, `display: "standalone"`, 192/512 icons; no external fonts, images, or scripts load.
