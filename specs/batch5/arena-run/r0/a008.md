# CP Compass PWA: service-worker caching design

## Assumptions

The shell is identical for every user — `index.html` holds no user data, so caching it cannot leak one account to another. All user data arrives via `/api/v1`. Font filenames may change per build, so fonts are runtime-cached, not precached.

## Cache names and versioning

Exactly one cache ever exists: **`cp-shell-<BUILD_ID>`**, e.g. `cp-shell-a1b2c3d`, where `BUILD_ID` is the git short SHA of the deployed commit. `frontend/public/sw.js` holds the placeholder `__BUILD_ID__`, replaced after `vite build` by `scripts/inject-sw-build-id.mjs`:

```js
import { execSync } from 'node:child_process'; import fs from 'node:fs';
const id = process.env.BUILD_ID || execSync('git rev-parse --short HEAD').toString().trim();
const p = 'dist/sw.js';
fs.writeFileSync(p, fs.readFileSync(p, 'utf8').replaceAll('__BUILD_ID__', id));
```

`package.json`: `"build": "vite build && node scripts/inject-sw-build-id.mjs"`. A new deploy changes the `sw.js` bytes, triggering the browser to detect an update; the old cache name stops matching, so activation deletes it. Never reuse a cache name or create a second, unversioned cache — that is how stale shells survive.

## Precache list (install time)

Precached: `/`, `/index.html`, `/manifest.webmanifest`, `/compass.svg`. Not precached: `/assets/*` and `/fonts/*` (hashed/variable names — runtime-cached on first fetch), `/api/*` (never cached).

## `frontend/public/sw.js` (complete)

```js
const CACHE = `cp-shell-__BUILD_ID__`; // placeholder replaced at build time
self.addEventListener('install', (e) => {
  e.waitUntil(caches.open(CACHE)
    .then((c) => c.addAll(['/', '/index.html', '/manifest.webmanifest', '/compass.svg']))
    .then(() => self.skipWaiting()));
});
self.addEventListener('activate', (e) => {
  e.waitUntil(caches.keys()
    .then((keys) => Promise.all(keys.filter((k) => k.startsWith('cp-shell-') && k !== CACHE).map((k) => caches.delete(k))))
    .then(() => self.clients.claim()));
});
self.addEventListener('fetch', (e) => {
  const { request } = e, url = new URL(request.url);
  if (request.method !== 'GET' || url.origin !== self.location.origin
      || url.pathname.startsWith('/api/') || request.headers.has('Authorization')) return;
  if (request.mode === 'navigate') {
    e.respondWith(fetch(request).then((r) => {
      if (r.ok && r.headers.get('content-type')?.includes('text/html')) {
        const copy = r.clone();
        caches.open(CACHE).then((c) => c.put('/index.html', copy));
      }
      return r;
    }).catch(() => caches.match('/index.html')));
    return;
  }
  if (url.pathname.startsWith('/assets/') || url.pathname.startsWith('/fonts/')) {
    e.respondWith(caches.match(request).then((hit) => hit || fetch(request).then((r) => {
      if (r.ok) { const copy = r.clone(); caches.open(CACHE).then((c) => c.put(request, copy)); }
      return r;
    })));
    return;
  }
});
```

Three independent defences, so no single bug leaks data: (1) any `/api/` URL returns before `respondWith` is ever called — zero worker latency or interference; (2) any request with an `Authorization` header does the same, at any path; (3) only `GET`, same-origin, `200 OK` responses are cached, and navigations are stored only as `/index.html`, never under the deep-link URL. The worker never reads, stores, or replays `Authorization` headers. The SSE stream at `/api/v1/sync/stream` is a `GET` under `/api/`, so (1) bypasses it.

## Fetch routing — why each strategy

| Request | Strategy | Why |
|---|---|---|
| `/api/*` (incl. SSE, `/demo/*`) | Network-only, no `respondWith` | Live data — caching it is the leak this design prevents |
| Navigations (`/`, `/app/*`) | Network-first, fallback to cached `/index.html` | Freshest shell online; shell still loads offline |
| `/assets/*` | Cache-first | Hashed names are immutable — revalidation is waste |
| `/fonts/*` | Cache-first | Same; a new deploy clears the versioned cache anyway |
| Everything else | Network-only | Default-deny: unlisted URLs are never cached by accident |

## Update flow

New deploy → new `BUILD_ID` → `sw.js` bytes change → browser installs the new worker on next navigation or `registration.update()` → it precaches into the new cache, `skipWaiting()` activates it → activation deletes every old `cp-shell-*` cache → `clients.claim()` takes control. Open tabs get `controllerchange`, and `main.tsx` shows a small toast, "New version available — Refresh", with a Refresh button. No auto-reload: reloading mid-sync would kill the SSE stream and lose in-progress state. Tabs already open keep running old JS until refresh — deliberate, not a bug. `main.tsx` (production only):

```tsx
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js').then((reg) => {
      setInterval(() => reg.update(), 60 * 60 * 1000);
      document.addEventListener('visibilitychange', () => { if (!document.hidden) reg.update(); });
    });
    navigator.serviceWorker.addEventListener('controllerchange', () => showUpdateToast(() => location.reload()));
  });
}
```

Update checks hit Vercel static hosting, never Render. No background sync, no periodic sync — nothing ever wakes Render.

## Offline behaviour

After one online visit, the whole shell loads offline. Tapping a deep link such as `/app/dashboard` offline serves the cached `index.html`; the router renders Dashboard, its `/api/v1` calls fail (network-only, uncached), and the app must show an explicit offline empty state ("You're offline — your data will load when you're back"), never stale data from another session. No offline data, no offline queue, no cached dashboard. Before any online visit, nothing is cached — the browser shows its own offline page. On a shared device, logout is safe by construction: no user data was ever cached.

## Manifest (installability fix)

Chrome requires 192 px and 512 px PNG icons — `compass.svg` alone will not install the app. Ship `/icons/icon-192.png` and `/icons/icon-512.png` (`purpose: "any maskable"` on the 512 px one); keep `start_url` and `scope` at `/`.

## What is deliberately NOT cached, and recovery if the worker is buggy

Never cached: every `/api/v1` response, the SSE stream, any request with an `Authorization` header, any non-`GET` request, any cross-origin request, any non-`200` response. If a buggy worker ships, deploy this kill-switch as the new `/sw.js` (new `BUILD_ID`, so it installs like any update): on install `skipWaiting()`, on activate delete every `cp-*` cache and call `self.registration.unregister()`. Users can also recover via DevTools → Application → Clear site data.

## Trade-offs (chosen explicitly)

- **Network-first navigations over cache-first:** costs a round-trip per online load; buys a shell that can never be silently stale.
- **Cache-first hashed assets over stale-while-revalidate:** gives up revalidation; buys zero-latency repeat loads. Safe only because the hash makes content immutable; the versioned cache is the backstop if an asset were ever served unhashed.
- **No auto-reload:** gives up instant updates; buys never interrupting a sync or losing form state.
- **No offline data:** gives up an offline dashboard; buys the privacy guarantee. A cached dashboard is exactly the cross-user leak this design refuses to build.
- **Hand-written worker over Workbox:** gives up precache-manifest generation; buys zero dependencies and a worker short enough to audit line by line.

## Verification

1. **No `/api` cached:** use the app online, then DevTools → Application → Cache Storage → `cp-shell-*`: only `/`, `/index.html`, manifest, `compass.svg`, `/assets/*`, `/fonts/*` — zero `/api/` entries. Console: `await caches.match('/api/v1/dashboard')` returns `undefined`.
2. **Shell loads offline:** DevTools → Network → Offline, reload `/app/dashboard`: shell renders with the offline empty state. Log out, reload offline, confirm no previous user's data appears.
3. **New deploy updates the shell:** ship a commit (new `BUILD_ID`), reload: the toast appears, Cache Storage shows the new `cp-shell-*` name, the old one is gone.

## Requirements checklist

1. No authenticated response cached, no cross-user leak — three defences in `sw.js`; step 1.
2. Shell loads offline after one online visit; step 2.
3. New deploy reaches users — versioned cache + `skipWaiting` + activation delete; step 3.
4. SSE and all `/api` bypass the worker — early return, no `respondWith`; step 1.
5. Hashed assets + one `index.html` — runtime cache-first by full hashed URL; navigations cached only as `/index.html`.
6. No background/periodic sync waking Render — none exists; update checks hit Vercel only.
