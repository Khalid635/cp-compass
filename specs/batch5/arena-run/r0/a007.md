# CP Compass PWA — Service-Worker Caching Design

## The design in one paragraph

One hand-written worker at `/sw.js` (no Workbox, no new dependencies) caches only the static shell — `index.html`, hashed JS/CSS, fonts, logo, manifest — in a versioned cache replaced per deploy. Every `/api/` request, including the SSE sync stream, bypasses the worker and is never stored, so no authenticated response can leak across users or survive logout. Navigations are network-first (3 s timeout), falling back to the cached shell, so the app boots offline. The worker activates at once, deletes old caches, and offers a "New version available — Refresh" toast.

## Assumptions

- `index.html` holds no per-user content; if that changes, this design is unsafe.
- The manifest already exists; confirm `start_url: "/"` and `scope: "/"`.
- Vercel serves `index.html` for all SPA routes.

## 1. Cache names and versioning

- Shell: `cp-compass-shell-<VERSION>` — one per deploy, deleted on the next.
- Fonts: `cp-compass-fonts-v1` — long-lived; bump only if a font changes.

`<VERSION>` is the git short SHA, injected at build time (§7); each deploy creates a new shell-cache name, and `activate` deletes every other `cp-compass-*` cache. There is no unversioned cache, so a stale shell cannot survive. Confidence: high — it fails safe (worst case: a redundant re-download, never a stale shell).

## 2. Precache list (install time)

Precached via `cache.addAll`; if any entry fails, install fails and the old worker stays: `/`, `/index.html` (same file; both keys, so the fallback always hits), `/manifest.webmanifest`, `/compass.svg`.

**Not** precached: `/assets/*` and `/fonts/*`. Their hashed filenames are unknown at author time; enumerating them needs a build-time manifest generator — a new failure mode for zero benefit. They are cached on first fetch, cache-first (§3): after one online visit they are cached as if precached, and the hash changes every build. Also excluded: anything under `/api/` (incl. public `/demo/*` — §6), URLs with query strings, non-GET requests.

## 3. Fetch-handler routing

Only same-origin `GET` requests are handled; all others are left alone (no `respondWith`), so the browser fetches normally.

| Request | Strategy | Why |
|---|---|---|
| `/api/*`, incl. `/api/v1/sync/stream` (SSE) | **Network-only, no `respondWith`** | Privacy invariant: the worker never reads headers or touches these URLs, so it cannot see, store, or replay an `Authorization` header. SSE untouched; the backend wakes only on user action. |
| Navigations (`request.mode === 'navigate'`) | **Network-first, 3 s timeout, fallback to cached `/index.html`** | Fresh shell online; offline, the cached shell boots and the router renders the route. Navigation responses are never cached. |
| `/assets/*` | **Cache-first, populate on miss** | Hash-named files are immutable. On a miss, fetch and store a clone if `res.ok`. |
| `/fonts/*` | **Cache-first in the fonts cache, populate on miss** | Immutable woff2; same reasoning. |
| Other same-origin GET | **Stale-while-revalidate in the shell cache** | Instant serve, background refresh. |

## 4. Update flow

1. **Build:** inject the git SHA as `<VERSION>` (§7) → new shell-cache name.
2. **Install:** precache the shell, then `skipWaiting()`.
3. **Activate:** delete old `cp-compass-*` caches, then `clients.claim()`.
4. **User experience:** no forced reload. `main.tsx` listens for `controllerchange` and shows "New version available — Refresh"; tapping it reloads. No auto-reload: a forced reload mid-sync could lose state. Ignoring the toast costs at most one session — the new worker already controls the next visit.

## 5. Offline behaviour

After one online visit, the shell loads offline: `index.html` from the precache, JS/CSS/fonts/logo from their caches. A deep link such as `/app/dashboard` while offline: the navigation fetch fails, the worker serves cached `/index.html`, and the router renders the dashboard route. Its `/api/v1` calls bypass the worker and fail — the app must show an explicit offline state ("You're offline", with Retry), **never** stale numbers; no data is cached, by design. First-ever visit while offline: nothing is cached, so the browser shows its standard offline page.

## 6. What is deliberately NOT cached, and failure recovery

**Never cached:** every `/api/v1` response; public `/demo/*` too — one rule ("no `/api/` response in any cache") is auditable where a per-route allowlist is not; `Authorization` headers; non-GET requests; cross-origin responses. On a shared device this makes logout safe: after logout, an offline reload shows the shell and login screen, with none of the previous user's data in storage.

**If the worker is buggy:** every failure degrades to "no worker", never "wrong data": a fetch-handler exception falls through to the network; a broken install leaves the previous worker running; a bad worker is fixed by shipping a corrected one. Kill switch: deploy a minimal `/sw.js` whose `activate` handler deletes all `cp-compass-*` caches and calls `self.registration.unregister()`, then ship the fixed worker. User-side recovery: DevTools → Service Workers → Unregister, or Clear site data. The kill switch only reaches users who come back online.

## 7. The files

**`frontend/public/sw.js`** (complete; `__APP_VERSION__` replaced at build):

```js
// Shell worker. Invariant: NOTHING under /api/ is ever cached.
const VERSION = '__APP_VERSION__';
const SHELL = `cp-compass-shell-${VERSION}`;
const FONTS = 'cp-compass-fonts-v1';
const PRECACHE = ['/', '/index.html', '/manifest.webmanifest', '/compass.svg'];
const put = (cache, req, res) => { if (res.ok) { const c = res.clone(); caches.open(cache).then((ca) => ca.put(req, c)); } return res; };

self.addEventListener('install', (e) => {
  e.waitUntil(caches.open(SHELL).then((c) => c.addAll(PRECACHE)).then(() => self.skipWaiting()));
});
self.addEventListener('activate', (e) => {
  e.waitUntil(caches.keys()
    .then((ks) => Promise.all(ks.filter((k) => k.startsWith('cp-compass-') && k !== SHELL && k !== FONTS).map((k) => caches.delete(k))))
    .then(() => self.clients.claim()));
});
self.addEventListener('fetch', (e) => {
  const { request } = e, url = new URL(request.url);
  if (request.method !== 'GET' || url.origin !== self.location.origin) return;
  if (url.pathname.startsWith('/api/')) return;
  if (request.mode === 'navigate') {
    e.respondWith(fetch(request, { signal: AbortSignal.timeout(3000) }).catch(() => caches.match('/index.html')));
    return;
  }
  if (url.pathname.startsWith('/assets/') || url.pathname.startsWith('/fonts/')) {
    const cache = url.pathname.startsWith('/fonts/') ? FONTS : SHELL;
    e.respondWith(caches.match(request, { cacheName: cache })
      .then((hit) => hit || fetch(request).then((res) => put(cache, request, res))));
    return;
  }
  e.respondWith(caches.match(request).then((hit) => {
    const net = fetch(request).then((res) => put(SHELL, request, res)).catch(() => hit);
    return hit || net;
  }));
});
```

**Build injection:** `scripts/inject-sw-version.mjs` (after `vite build`) replaces `__APP_VERSION__` in `dist/sw.js` with the git short SHA (fallback: build timestamp). `package.json`: `"build": "vite build && node scripts/inject-sw-version.mjs"`.

**`frontend/src/main.tsx`** — register only in production, never in dev:

```tsx
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js');
  let refreshing = false;
  navigator.serviceWorker.addEventListener('controllerchange', () => {
    if (refreshing) return; refreshing = true;
    showUpdateToast('New version available', () => window.location.reload());
  });
}
```

No new dependencies. No background/periodic sync or push — nothing wakes the sleeping backend.

## 8. Verification

**(a) No `/api/` response is cached.** Use the app online. DevTools → Application → Cache Storage: both caches must hold only `/`, `/index.html`, `/manifest.webmanifest`, `/compass.svg`, `/assets/*`, `/fonts/*` — zero URLs containing `/api/`. Console (expect `[]`): `caches.keys().then(ks => Promise.all(ks.map(k => caches.open(k).then(c => c.keys())))).then(a => a.flat().map(r => r.url).filter(u => u.includes('/api/')))`. Also: log in as A, log out, log in as B — B sees no trace of A's data.

**(b) Shell loads offline.** After one online visit, go offline in DevTools, reload, and open `/app/dashboard`: the shell renders with an offline state and Retry. Repeat with a hard reload and in airplane mode.

**(c) New deploy updates the shell.** Deploy a visible change (e.g. a footer version string). Reload, tap Refresh on the toast, and confirm the new string, a new `cp-compass-shell-<VERSION>`, and the old cache gone. Check `navigator.serviceWorker.controller.scriptURL` matches the new deploy. Re-run (a) and (b) on every release.
