# CP Compass PWA: service-worker caching design

## Decision

Cache only the public shell, never any API response; routing is by URL only, never by headers or identity. The obvious default fails three ways: precaching `index.html` cache-first strands users on a stale shell after a deploy; caching public `/demo/*` responses because they are "harmless" turns the `/api/*` rule from a one-line audit into a judgement call on devices that may be shared; and a hand-written worker cannot precache hashed `/assets/*` filenames it cannot know at authoring time. So: `index.html` is network-first, hashed bundles are cached on first fetch, `/api/*` is not handled at all, and a new worker waits for the user instead of seizing the page.

## Assumptions

`frontend/public/sw.js` is copied verbatim to `/sw.js` (no build step, no Workbox, no new dependencies). The manifest already exists; add `<link rel="manifest" href="/manifest.webmanifest">` to `index.html` if absent. Fonts are `/fonts/Manrope.woff2`, `/fonts/SplineSansMono.woff2`, `/fonts/Michroma.woff2`; `@fontsource` files are hashed bundles under `/assets/`.

## Cache names and versioning

One cache, one line bumped per release:

```js
const VERSION = 'v1'; // bump on every release
const SHELL_CACHE = `cp-compass-shell-${VERSION}`;
```

Bumping `VERSION` changes `sw.js` bytes, which is what makes the browser install the new worker. On activation it deletes every other `cp-compass-*` cache, so a deploy invalidates the old shell in exactly one place. No per-asset pruning: hashed bundles are immutable, old hashes are never requested again, and they die with the old cache.

## Precache list

Precached at install — stable URLs only, all public and user-independent: `/index.html`, `/compass.svg`, `/manifest.webmanifest`, and the three fonts above. (`/` needs no separate entry: the offline fallback is the cached `/index.html`.)

Not precached: `/assets/*` (hashes unknown at authoring time; cached on first fetch), `/api/*` including `/demo/*` (below), and `/og.png` and `/showcase-*.png` (large marketing images; the landing page must not depend on them — they render as broken images offline, with alt text).

## Fetch routing

The worker never reads a request header and cannot see the `Authorization` header. Anything not listed gets no `respondWith`: the browser's default network fetch, untouched.

| Request | Strategy | Why |
|---|---|---|
| Non-`GET`, cross-origin | No handler | Nothing to cache |
| `/api/*`, incl. `/api/v1/demo/*`, `/api/v1/sync/stream`, `/health` | Network-only: return early, no `respondWith` | The privacy guarantee — one demo exception would make the rule unauditable. The SSE stream passes through with zero added latency; demo pages show the offline notice instead of stale data |
| Navigations (`mode === 'navigate'`) | Network-first, cache fallback | Online, the user always gets the newest `index.html`, so a deploy lands on the next online navigation even before the new worker activates. Offline, serve cached `index.html` |
| `/assets/*` | Cache-first, populate on miss | Content-hashed filenames can never be stale |
| `/fonts/*` | Stale-while-revalidate | Filenames are unhashed, so a font can change under the same URL; background revalidation picks it up within one visit |
| `/compass.svg`, `/manifest.webmanifest` | Cache-first | Precached, stable, public |

## `frontend/public/sw.js`

```js
// Privacy rule: never reads headers, never touches /api/*, stores only the public shell.
const VERSION = 'v1'; // bump on every release
const SHELL_CACHE = `cp-compass-shell-${VERSION}`;
const PRECACHE = ['/index.html', '/compass.svg', '/manifest.webmanifest',
  '/fonts/Manrope.woff2', '/fonts/SplineSansMono.woff2', '/fonts/Michroma.woff2'];
self.addEventListener('install', (e) => {
  // No skipWaiting: the new worker waits until the user taps Update, so the
  // old worker keeps serving open tabs.
  e.waitUntil((async () => {
    const cache = await caches.open(SHELL_CACHE);
    await cache.addAll(['/index.html', '/compass.svg', '/manifest.webmanifest']);
    await Promise.all(PRECACHE.filter((u) => u.startsWith('/fonts/'))
      .map((u) => cache.add(u).catch(() => {}))); // best-effort; SWR covers fonts
  })());
});
self.addEventListener('activate', (e) => {
  e.waitUntil((async () => {
    for (const k of await caches.keys())
      if (k.startsWith('cp-compass-') && k !== SHELL_CACHE) await caches.delete(k);
    // No clients.claim(): open tabs keep the old worker until their next navigation.
    for (const c of await self.clients.matchAll()) c.postMessage({ type: 'SW_ACTIVATED' });
  })());
});
self.addEventListener('message', (e) => {
  if (e.data?.type === 'SKIP_WAITING') self.skipWaiting();
});
self.addEventListener('fetch', (e) => {
  const { request } = e;
  const url = new URL(request.url);
  if (request.method !== 'GET' || url.origin !== self.location.origin) return;
  if (url.pathname.startsWith('/api/')) return; // network-only, untouched
  if (request.mode === 'navigate') return e.respondWith(networkFirst(request));
  if (url.pathname.startsWith('/assets/')) return e.respondWith(cacheFirst(request));
  if (url.pathname.startsWith('/fonts/')) return e.respondWith(staleWhileRevalidate(request));
  if (PRECACHE.includes(url.pathname)) return e.respondWith(cacheFirst(request));
  // Everything else: browser default. Do not cache surprises.
});
async function networkFirst(req) {
  const cache = await caches.open(SHELL_CACHE);
  try {
    const res = await fetch(req);
    if (res.ok && res.headers.get('content-type')?.includes('text/html'))
      await cache.put('/index.html', res.clone()); // canonical key for the offline fallback
    return res;
  } catch {
    return (await cache.match('/index.html')) ?? Response.error();
  }
}
async function cacheFirst(req) {
  const cache = await caches.open(SHELL_CACHE);
  return (await cache.match(req)) ?? fetch(req).then(async (res) => {
    if (res.ok) await cache.put(req, res.clone());
    return res;
  });
}
async function staleWhileRevalidate(req) {
  const cache = await caches.open(SHELL_CACHE);
  const network = fetch(req).then(async (res) => {
    if (res.ok) await cache.put(req, res.clone());
    return res;
  }).catch(() => null);
  return (await cache.match(req)) ?? (await network) ?? Response.error();
}
```

## Update flow

1. The browser re-checks `/sw.js` on every navigation. A changed worker installs in the background and waits.
2. The app shows a persistent, non-modal banner: "A new version of CP Compass is available — [Update]". Dismissing it snoozes it until the next navigation; it cannot be dismissed forever.
3. Tapping **Update** posts `{ type: 'SKIP_WAITING' }` to the waiting worker. It activates, deletes old caches, posts `SW_ACTIVATED`, and the app reloads that tab once. Other tabs pick the new shell up on their next navigation. No silent auto-reload and no `clients.claim()`: seizing a tab mid-sync could drop the SSE stream and swap code under running JS. A sync interrupted by the reload resumes from the server — progress is server state, re-read from `/api/v1/sync/status`.

## Offline behaviour

After one online visit, offline the shell loads: `index.html`, JS/CSS, the three fonts, and the logo. A deep link such as `/app/dashboard` works the same way — the worker serves cached `index.html` for any navigation and React Router renders the route. With a token in `localStorage`, the dashboard shell renders with an "You're offline" notice and no data (every `/api/v1` call fails as a network error, which the API client must render as offline, not crash on); without a token, the login page renders. The landing page loads fully offline except the showcase screenshots. Nothing user-specific is ever rendered from cache, because nothing user-specific is in it — which is why **logout does not clear it**: the shell is public, and the next user on a shared device gets the same shell and fresh data from the network.

## Not cached, and recovery from a buggy worker

Not cached: every `/api/v1` response (dashboard, submissions, settings, sync status, hints, post-mortems, demo data, SSE), any non-`GET` request, any cross-origin response, and any response that is not `200 OK`. No background sync, no periodic sync — nothing ever wakes the sleeping Render backend.

If the worker is buggy: ship a fixed `sw.js` with a bumped `VERSION` and the banner flow replaces it. If the worker breaks loading itself, deploy a kill-switch `/sw.js` that on install calls `skipWaiting()`, and on activate deletes every cache and calls `self.registration.unregister()` — the browser picks it up on the next navigation. Per-device fallback: DevTools → Application → Service Workers → Unregister, then Clear site data. The worker is never registered in dev.

## `main.tsx`

```tsx
if (import.meta.env.PROD && 'serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js').then((reg) => {
    const announce = () => window.dispatchEvent(new CustomEvent('sw-update-available'));
    if (reg.waiting) announce();
    reg.addEventListener('updatefound', () => {
      reg.installing?.addEventListener('statechange', () => { if (reg.waiting) announce(); });
    });
    navigator.serviceWorker.addEventListener('message', (e) => {
      if (e.data?.type === 'SW_ACTIVATED') location.reload();
    });
  });
  // Banner's Update button:
  window.addEventListener('sw-apply-update', () => {
    navigator.serviceWorker.getRegistration()
      .then((r) => r?.waiting?.postMessage({ type: 'SKIP_WAITING' }));
  });
}
```

The banner is a small component listening for `sw-update-available` and dispatching `sw-apply-update` on click. No other app change, except the API client must treat a failed fetch as "offline" and show the offline notice instead of crashing.

## Verification

1. **No API response is cached.** Use the app online, then in DevTools Console run: `for (const k of await caches.keys()) console.log(await (await caches.open(k)).keys())` — every URL must be `/index.html`, `/compass.svg`, `/manifest.webmanifest`, `/fonts/*`, or `/assets/*`; none may contain `/api/`. Also confirm a logout/login as a different user shows that user's data.
2. **Shell loads offline.** Visit online once, go offline, reload `/` and open `/app/dashboard`: shell, fonts, and logo load; data areas show the offline notice; nothing crashes.
3. **A new deploy updates the shell.** Bump `VERSION`, change a visible string, deploy, reload online: the banner appears; tap Update, confirm the new string and that only the new `cp-compass-shell-*` cache remains. Confirm `/sw.js` returns JavaScript, not `index.html`.
4. **SSE bypass.** Start a sync: `/api/v1/sync/stream` streams with no worker delay and leaves no cache entry.
